# 附录 · 条件反射自查卡

> 触发场景 → 条件反射。从十八轮拷问复盘与全十七章知识中提炼，把「知道」压缩成「看到就想到」。
> 做架构决策前扫一遍；评审方案、写重试/缓存/同步代码前扫一遍。
> 来源：[grilling-review.md](../grilling-review.md) 的缺口补全自查卡（含进阶篇补充）。

## 估算与选型

| 触发场景 | 条件反射 |
|---------|---------|
| 算出 QPS/容量数字 | 先问「这真的是问题吗」（证伪复杂度），再算扇出、再算数据总量 |
| 看到数字（QPS/写量） | 先问「读还是写」——同数字不同性质，结论相反 |
| 看到「一对多」业务关系 | 算写放大：推/拉/推拉结合；长连接系统扩容指标是连接数不是 QPS |
| 想照搬成熟架构 | 先比约束：团队/流量/成本/生命线；「不加会死吗」问到系统还需不需要存在 |
| 昂贵资源在运转 | 问：这一秒它在为谁工作？那个人还要这个结果吗？（不要则 abort） |
| 拆分/并行方案 | 先数通信：传几次、传多少；通信模式决定部署边界 |

## 数据与一致性

| 触发场景 | 条件反射 |
|---------|---------|
| 看到「剩余 N 个」 | 限量发放族 → 强一致+原子扣减（库存/券/名额/预订全同族） |
| 判一致性 | 三把尺子依次过：①赔钱吗 ②能自愈吗 ③是 hint 还是判定；同一数据不同用途分档 |
| 需要对账的数据 | = 错了不会自愈 = 强一致 |
| 任何最终一致承诺 | 必配兑现机制：对账 / ack+重试；「最终」不会自己到达 |
| 超时 | ≠ 失败；置「未知」，查询收敛，对账兜底 |
| 会被重试的写操作 | 幂等三要素：调用方签发键、唯一约束验票、键是动作身份证；**查重和写入必须原子——用唯一约束，不用先查后写** |
| 既改库又发消息 | 双写陷阱：先写谁都漏窗口（丢消息/幽灵消息）→ Outbox 同一本地事务，重试补不上结构缺口 |
| 客户端先写的请求 | 两把尺子：决定权在谁？涉钱涉权限吗？客户端可以是仓库，不能是法官 |
| 多端/离线同步 | 操作日志 + 游标（只传增量）+ 墓碑（两端不物理删） |
| 并发写冲突 | 先问能不能存操作而非状态（冲突自动消解）；累加型禁用 LWW |
| 要防碰撞/防重复 | 先想结构不相交（命名空间隔离/唯一约束），别做先查后写 |
| 给缓存设 TTL | 先问：数据不可变吗？不可变→永不过期；可变→逻辑过期/抖动 |
| 两种访问形态冲突 | 两套存储（CQRS）；不为 1% 查询毁 99% 主路径 |
| 跨服务业务动作 | 没有跨服务事务：Saga 拆本地事务+反向补偿（补偿≠回滚）；步骤多要编排，中间态要正面设计 |
| 补偿跨服务动作（Saga） | 先确认：这一步是「确认失败」还是「超时未知」？未知必先查询确认再补偿，否则补偿了一笔其实成功的支付 |
| 补偿/回滚动作本身 | 补偿也要幂等：每个补偿动作自带幂等键、重试用同一键——否则补偿超时+重试=补偿两次，二次资损 |
| 改表结构/事件结构/API 契约 | expand-contract（扩展→双写→收缩）+ 灰度；永不做一步到位的破坏性变更 |

## 扩展与韧性

| 触发场景 | 条件反射 |
|---------|---------|
| 写瓶颈 | 复制和缓存直接出局；分片前先消解：「为什么有这么多写」 |
| 打散/分片/分段 | 第二层账单：倾斜+再平衡是出厂配套 |
| 依赖变慢、线程被占住 | 慢比宕机更致命：熔断+舱壁+降级把它关进笼子，别让它顺调用链传染 |
| 写重试代码 | 退避+抖动+重试预算+幂等前提，四样缺一不可；`retry(3)` 裸重试是风暴元凶 |
| 过载来者不拒 | 降载/背压：优雅地拒绝一部分，远胜假装全扛然后一起崩 |
| 定可用性目标 | 杠杆在 MTTR（坏了多快恢复）不在 MTBF；错误预算留迭代空间，别追 100% |
| 容灾预案/降级开关 | 没演练过的约等于没有（混沌工程验收）；降级预案要风平浪静时埋好 |
| 危险操作/重要变更 | 爆炸半径控制：灰度/金丝雀/护栏下限——一条命令能误伤多大，事故就能多大 |
| 扇出接口时快时慢 | 别先诊热点：整体等最慢的 = 尾延迟放大 → 对冲请求/超时预算/慢副本剔除（诊断先于用药：先问哪层的病） |
| 自动化故障处置（切主/扩容/下线） | 三护栏：危险操作装下限、多源确认再动（灰色失败不凭一次超时）、恢复路径不依赖被恢复的系统 |
| 读重大事故案例 | 各记一句话：S3=护栏下限、Meta=恢复不依赖被恢复系统、Cloudflare=变更要灰度、GitHub=自动化的前提假设会失效 |

## 安全与信任边界

| 触发场景 | 条件反射 |
|---------|---------|
| 有人拿「在内网/内网互通」当安全理由 | 横向移动：突破一处就能在「可信内网」走廊式收割；墙已塌（远程办公/上云/东西向流量），零信任——信任绑身份+设备+上下文，每次访问重新挣得 |
| 共用账号 / 一把钥匙全公司 / 长期不换的凭证 | 爆炸半径语言：一套凭证=全公司一个巨型半径；四种拆小：最小权限、网络分段、凭证隔离、短时凭证 |
| 密钥出现在代码 / 配置文件 / 日志 / 报错 | secrets 三铁律整组上：集中保管（KMS 运行时注入）、定期轮换、最小暴露；会被 grep/commit/打日志的明文=已泄露（Git 历史删不掉，删文件≠删历史，轮换才是止损） |
| 多租户系统 / 看到 tenant_id | 档位按串扰代价定（谱系可谈），但「结构强制」不可谈：平台层/ORM 自动注入租户过滤+跨租户读不到的自动化测试；漏点不报错、单租户自测发现不了 |
| AI 推荐的包 / 不太眼生的依赖 | slopsquatting：先核实真实存在+可信再进 lockfile；信任是传递的（你只写了 5%，95% 攻击面是别人的） |

## AI 时代判断

| 触发场景 | 条件反射 |
|---------|---------|
| LLM 系统验收（「试了几十轮觉得挺好」） | 评测三件套：评测集+评分（LLM-as-judge）进 CI 看分布防退化、护栏人审（不可逆操作人工确认）、可观测可回退；换模型就是换代码，只是不经过你的 CI——评测集是隐性供应链的门禁（卡退化不卡提升，持平放行） |
| 知识库/文档想全量塞进上下文窗口 | 上下文工程=新内存层级：能装下≠装得起（token 成本一等公民，每次全量付费随流量线性放大）+ 塞了≠用了（迷失在中间：U 形注意力，常用内容埋中段看不见）；对药：RAG 按需取+热点片段本地缓存+固化 QA 对 |
| 长上下文 vs RAG vs 微调怎么选 | 全是取舍：长上下文简单但贵+迷失；RAG 精准但要养检索；微调不在内存层级里——训练时烧进权重（僵化，改版就得重训）；没有最好只有最合适 |
| 想上自主 Agent /「全自动才酷」 | 能用确定的工作流解决就别上自主 Agent——固定管道用工作流，自主性只买需要的那点灵活性；分界=副作用可逆不可逆（不可逆涉钱留人工确认）；Agent 的灵魂在刹车：步数/成本/超时上限+工具幂等+沙箱最小权限 |

## 沟通与决策

| 触发场景 | 条件反射 |
|---------|---------|
| 两个需求冲突 | 先问能不能消解（正交通道/状态分级/客户端副本），消解不了再给带价签选项 |
| 给老板/业务方出方案 | 菜单不是报价：方案/他得到/他付出/成本，至少三条路；绝不说「做不到」 |
| 画图框超 9 个 | 拆论证不是合并框；一张图一个结论，箭头标方向和含义 |
| 两个模块解耦不干净 | 先看人：owner 是谁、沟通多紧密；逆康威先组团队再拆系统 |
| 重要决策落地 | 写 ADR：「放弃了什么」是独有价值；技术债三件事：借、记账、排期还 |
| 有人提议推倒重写 | 三论点：移动靶（旧系统不会等你）、疤是痂（丑陋代码是隐性知识，重写=踩坑清零）、期间完全停止进步；唯一主路是渐进演进 |
| 换系统内/外实现 | 绞杀者在外面拦（命门=门面路由层）、抽象分支在里面换（禁长命分支，主干永远可发布）；切流前用并行运行拿真实流量比对——速度交给模型，信心交给数据 |
| 变更管理词汇易混 | 四词归位：灰度=怎么发布、双写=数据怎么过渡、expand-contract=结构怎么演进、绞杀者/抽象分支=代码怎么迁移 |
| 拆单体/划边界 | 按业务能力（限界上下文）找缝不按技术分层；先模块化单体把缝划对划稳，再按需抽服务；适应度函数进 CI 防边界腐化 |
| 想让接口变硬 / 靠立契约让团队少开会 | 契约是化石不是开关：先改组织沟通（拆 KPI、降会议频率、明确 ownership），沟通成本升上去接口才自然变硬；纸面契约压不住日常便利 |
| 团队疲于救火、讨论拆什么 | 负荷三归位：内在（领域，省不掉）只能分摊到更多桶、外在（偶然）平台收走、切换（上下文横跳）说明缝切歪了；先问哪个桶爆了再拆 |
| 题目/对方点名要几条、几个论点 | 先写①②③编号占位再填，填完**回读题面数一遍现象/要求对号入座**——占位治「记得几问」，回读治「内容够不够」（着急时最靠不住的是脑内 hold 住清单，结构要外化） |
| 答「为什么/怎么防/怎么修」的任何一点 | 机制名先行：先报横移/传导/自动化放大器/爆炸半径/漏点/迷失在中间/重试风暴/放大对称再展开——机制名是压缩包也是检索钥匙；记不牢配案例锚（xz=人被腐蚀、Log4Shell=依赖深处、SolarWinds=构建+自动、Capital One=权限+半径） |
| 把某章机制名用到新领域（跨章调用） | 药箱同迁：机制名迁过来，药要换成本地的药——热点迁到 RAG：本地缓存+固化 QA（不是一致性哈希）；先问这药治的是「数据怎么放」还是「访问怎么集中」 |
| 出安全/加固/修复方案 | **报科室再掏件**：先认科室再报套名——12 章可用性套件（熔断/舱壁/降级）治故障、16 章安全套件（最小权限/沙箱/白名单/人工确认）治攻击、secrets 三铁律/供应链五件套/STRIDE 六问——科室报错即警报（熔断拦不住注入），套名即清单防只掏一件 |

## 决策前三问

1. **「我手上有没有现成的结论/尺子能用？」** —— 治「有结论不主动调用」
2. **「这次的数字/性质和上次一样吗？」** —— 治教条惯性（读/写、可变/不可变、限量/非限量）
3. **「需求和限定条件确认全了吗？」** —— 治漏项（要几个点、什么边界、哪些不许碰）

> 一句话收尾：**判断力靠积累，条件反射靠刻意。** 尺子要主动掏、结论要绑场景、代价要先说、机制名要先行、结构优于检查、消解先于硬扛。
