# 03 · 读懂与画好架构图：C4 模型

> 参考章节：如何用 C4 模型把脑中的系统画成别人一眼就懂的图。

## 核心论点

画图的本质是**对齐**——让团队所有人看到同一个系统。想清楚却讲不明白，约等于没想清楚。画图本身还会逼你把含糊处想透。

## 烂图四宗罪

| 罪名 | 表现 |
|------|------|
| 没有边界 | 所有框平铺，分不清进程/机器/信任域 |
| 箭头没方向 | 不知道 A 调 B 还是 B 调 A，线上跑的是什么 |
| 抽象层次混乱 | 整个支付系统和某个工具函数画在同一层（最致命） |
| 框太多 | 40 个方块挤一页，信息量爆炸，看的人直接放弃 |

## C4 模型：四层缩放

核心思想：像地图软件的缩放级别，一张图只待在一个缩放级别。

| 层级 | 类比 | 画的是什么 | 给谁看 |
|------|------|-----------|-------|
| Context（上下文） | 中国地图 | 整个系统 + 周边用户/外部系统 | 所有人（含非技术） |
| Container（容器） | 市区图 | 系统由哪几个可独立运行的大块组成 | 技术团队 |
| Component（组件） | 街道图 | 一个容器内部由哪些模块组成 | 开发这块的工程师 |
| Code（代码） | 楼栋图 | 类、函数怎么组织 | 基本不画，交给 IDE |

> Container 不是 Docker 容器。指可以独立运行、独立部署的大块（前端应用、后端服务、数据库、缓存等）。

## 三层基本元素

| 元素 | 含义 | 要点 |
|------|------|------|
| 框 | 一个有职责的东西 | 必须能回答「你是干嘛的」；同一张图里尺度要一致 |
| 箭头 | 一段关系 | ① 必须有方向（谁主动找谁）② 必须标含义（调用？数据？事件？） |
| 边界 | 一条分界线 | 部署边界 / 信任边界 / 系统边界。新人最易忽略，但它最能体现架构思维 |

## 五条画图原则

1. **一张图只用一个抽象层次** — C4 的灵魂，专治抽象层次混乱
2. **箭头一定标方向和含义** — 没标注的线 = 没想清楚的依赖
3. **控制框的数量在 7±2** — 超过 9 个就该考虑往上抽一层或拆图
4. **先画 Context，再往下钻** — 自顶向下，别一上来就陷进细节
5. **永远为你的读者画图** — 给老板看的别出现技术黑话，给工程师看的别省掉关键数据流

**图的本质是一段论证**：一张图里的所有箭头，应共同支撑同一个结论。
- 框太多 = 这段论证太长 → **拆成多段论证（多张图）**，而不是硬合并框（会把不同关注点黏在一起）
- 图里既有「用户下单」又有「定时对账」又有「日志采集」= 一张图在讲三个故事——各是各的论证，拆开画

## 各层详解

### Context 图

整个系统 = 中间一个框，内部细节一概不画。周围画：谁在用 + 和哪些外部系统打交道。

回答最高层问题：系统干嘛的？和外面的世界怎么交互？

一个技术名词都没有，非技术人员也能看懂 → 最适合对齐「我们到底在做什么」。

### Container 图

放大上一层的系统框，钻进去看内部由哪几个可独立运行的大块组成、怎么通信、数据存在哪。

直接对应部署和运维：每个 Container 通常就是要部署、监控、扩容的单元。架构判断最密集的一层。

> 架构模板的全景图基本都画在 Container 层。

### Component 图

再放大，钻进某一个 Container 内部，看它由哪些模块构成（如订单模块、商品模块、认证模块）。

只有当某个 Container 复杂到值得拆解时才画。

### Code 图

基本不用手画。代码本身和 IDE 生成的关系图就是最准确、最实时的 Code 图。

> 别去手工维护一份代码一改就过时的文档。精力花在 Context 和 Container 上。

## ASCII 画图技巧

```
① 框：
   ┌─────────┐     横线 ─   竖线 │   四角 ┌ ┐ └ ┘
   │  服务 A  │     交叉 ┼   丁字 ┬ ┴ ├ ┤
   └─────────┘

② 箭头：标清方向
   ──▶  ◀──  ▲  ▼        单向依赖
   ◀──▶  或上下各一条      双向交互

③ 边界：虚线和实线区分
   ┌─────────┐           实线框：具体的东西
   └─────────┘
   ┌ ─ ─ ─ ─ ┐           虚线框：边界（系统/信任/部署）
   ┊         ┊
   └ ─ ─ ─ ─ ┘

④ 箭头旁加文字（最重要！）
   A ───调用 API───▶ B
   A ◀──返回结果──── B
```

实用建议：
- 先在草稿纸上想清楚布局再誊成 ASCII
- 善用对齐和留白，同一层框横向对齐
- 不必追求像素级完美，目标是讲清结构和关系

## 常见陷阱

- **一张图塞所有层次**：既画整个国家又画你家楼栋
- **箭头没标注**：没方向没含义的线 = 烂图头号来源
- **忽略边界**：边界画在哪 = 安全和部署决策的所在
- **框太多不忍拆**：超过 9 个就该分层或拆图
- **一上来就画细节**：应该先 Context 再下钻
