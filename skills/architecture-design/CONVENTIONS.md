# 更新规范

> 本文档规定了新增章节、模板时的格式要求，确保技能文件结构一致、主文件不膨胀。

## 核心原则

**SKILL.md 永远不维护目录列表。** 章节和模板的索引由各自的 INDEX.md 管理：

```
SKILL.md              → 只放指令（角色、流程、原则），不放目录
references/INDEX.md   → 管理所有参考章节的索引
templates/INDEX.md    → 管理所有架构模板的索引
```

无论后续增加多少内容，SKILL.md 的行数应保持 < 200 行。

---

## 新增参考章节

### 文件规范

- 路径：`references/XX-主题名.md`
- 编号：两位数递增（04, 05, 06...）
- 文件名：小写英文 + 连字符

### 文件结构

```markdown
# XX · 章节标题

> 参考章节：一句话说明本章核心内容。

## 核心论点
[本章最重要的一个结论]

## [按内容自由组织的小节]
...

## 常见陷阱
[本章涉及的典型陷阱]
```

### 更新步骤

1. 创建 `references/XX-主题名.md`
2. 在 `references/INDEX.md` 表格中添加一行索引
3. **不修改 SKILL.md**（除非章节引入了全新的工作流程或分析维度）
4. 如需更新 SKILL.md，只加指令性内容（新步骤/新原则），不加目录项

## 新增架构模板

### 文件规范

- 路径：`templates/XX-系统名.md`
- 编号：两位数递增（03, 04, 05...）
- 文件名：小写英文 + 连字符

### 标准 13 章节结构

每个模板必须包含：

| # | 章节 | 内容 |
|---|------|------|
| 1 | 一句话定位 | 用一句话说清系统是什么 |
| 2 | 业务本质 | 解决什么问题，钱从哪来 |
| 3 | 核心需求与约束 | 功能性需求 + 质量属性表 + 关键约束 |
| 4 | 架构全景图 | C4 Container 层 ASCII 图 |
| 5 | 组件职责 | 每个组件的职责和存在理由 |
| 6 | 关键数据流 | 2-3 个核心场景的步骤 |
| 7 | 数据模型与存储 | 数据类型 → 存储类型 → 为什么 |
| 8 | 关键决策与权衡 | 每个决策的方案对比 + 取向 + 代价 |
| 9 | 规模化与瓶颈 | 瓶颈出现的顺序和破解方法 |
| 10 | 安全与合规 | 该系统特有的安全风险 |
| 11 | 常见误区/反模式 | 反模式 → 正确做法 对照表 |
| 12 | 演进路线 | MVP → 成长期 → 成熟期 |
| 13 | 可复用要点 | 可迁移到其他系统的通用智慧 |

### 更新步骤

1. 创建 `templates/XX-系统名.md`
2. 在 `templates/INDEX.md` 表格中添加一行索引
3. **不修改 SKILL.md**

---

## 何时修改 SKILL.md

只在以下情况修改 SKILL.md：

| 情况 | 示例 |
|------|------|
| 新增工作流程步骤 | 第02章引入了六步框架，替换了原有4步 |
| 新增分析工具 | 第02章引入了灵魂六问 |
| 新增核心原则 | 第03章引入了 C4 画图能力 |
| 修正现有指令 | 质量属性表扩展、取舍矩阵修正 |

**不在 SKILL.md 中做的事：**

- 不添加章节/模板的目录列表（由 INDEX.md 管理）
- 不添加案例详情（放在 references/ 的章节文件中）
- 不添加模板内容（放在 templates/ 的文件中）

## 提交规范

Git commit message 格式：

```
feat: add chapter XX - 章节标题
feat: add XX 模板名 architecture template
refactor: 简要说明（非新增内容的重构）
```

## 架构输出规范

对系统进行完整架构分析时，使用 [TEMPLATE.md](TEMPLATE.md) 作为输出模板。

关键要求：
- 模板中 `[方括号]` 内容为待填充项
- 遇到无法确定的信息（规模、约束、质量属性优先级等）**必须向用户询问**，不可自行假设
- 参考原型只放查证过的真实链接，不编造 URL
- 每个设计必须回答「为什么」和「它在换取什么」
